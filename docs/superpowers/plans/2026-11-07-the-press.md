## E Employer sites get their read (behaviour, next after 2b)
- **Cause (spec, "Two facts"):** the read cut is fixed 67.5 s after the run starts (`src/sources/read_budget.py` `cut_at`). A repeat Find jobs run ran the boards step alone first, to ~60 s, so employer sites got ~4 s and places 0 s. A first Find jobs run reads its slice first and names employers at ~53-58 s. Moving the cut alone does not help: titles stop ~71 s after the run starts, so late-read jobs would wait unsorted (a prototype, all tests green, showed no test plays a late read).
- **E1, a repeat Find jobs run (owner, 8 Nov 2026: "One process, discovery inside (Recommended)"; "If there are jobs waiting to be scored, that should be the first new thing a repeated press does. Secondly, it should follow the path which will bring the more jobs to the user's list"):**
  - Tries: 1 moved the read's cut (wrong: titles stop ~71 s after the run starts); 2 started the boards step beside the search (wrong: the engine's run lock, `src/__main__.py` + `src/paths.py` `run_lock`, lets one search process run per data folder, so they still ran one after the other, in a random order).
  - **Design:** one Find jobs run after the first = one engine process (`src daily --discover-beside`). Its stages, one owner each: (1) the jobs waiting from earlier Find jobs runs are scored (`src/daily_search_scoring.py` `score_waiting_first`, #3058); (2) the found boards' first pages (`src/sources/boards_first.py`); (3) the employer sites, with the rest of the found boards (`boards_ahead.py`) and the fixed boards' employer discovery (jobs.ch, SwissDevJobs, TechTree: `src/sources/boards_beside.py`) beside them, in one side-by-side scope, all on the search's clock. The separate `src discover` step is gone from this Find jobs run: for most searches it read the same found boards the search reads (p7: 50 s, 0 jobs). Its employers land in `reports/companies.json` for the next search. A first Find jobs run keeps its order (E2).
  - Files: `desktop/lib/search-steps.js`, `desktop/lib/pipeline-args.js`, `src/daily_args.py`, `src/daily_search.py`, `src/sources/boards.py` (`discover()` split out of `main`), `src/sources/boards_beside.py`. Tests `desktop/test/unit/main/search-steps-beside.test.js`, `tests/unit/sources/test_boards_beside.py`; ledger L34; L03's test now names the search as the first step.
  - The owner's second goal (the path that brings the most jobs) is 2c's per-path number (jobs added per second of reading) feeding 3/6 and 5/6.
- **E2, first Find jobs run:** the full read after the slice; a separate owner decision with the numbers.
- **E2a, nothing waits inside 3 min (owner, 8 Nov 2026: "Both: no waits + background (Recommended)", then "3 min, then Find more"):** two PRs, each measured on its own by gi's by-hand Search check (`presses=2`, personas 7, 10, 12, 17; run 42451932088 before: p10 0/561, p12 0/94, p17 0/114, p7 0/13 employer sites read on the repeat run).
