# Spec · Job Pilotto Brain API, allowance and license keys (30 Sep 2026, staged)

> **Verdict (revised the same day, owner):** staged, per Notion 🧭 Strategy → 🪜 Stages.
> **Stage 1 (0→100 adopters):** AI stays in the app with the user's key (nothing passes our servers); the allowance
> is checked in the app; owner-signed license keys unlock it; only the employer index is served (step E).
> **Stage 2 (100→1,000):** included AI → steps A-full, B, C, F: the intelligence runs only on our server and the
> allowance is enforced there. The rest of this spec is the Stage 2 design.

## Decisions
| # | Decision | Chosen |
|---|---|---|
| 1 | Who pays the AI | Stage 1: **the user's own key, on their Mac**. Stage 2: **included AI** (we pay, capped), server-side |
| 2 | Privacy | key, CV, profile and job texts pass through the server **per request, in memory, never stored or logged**; said on the website |
| 3 | Limit | 30 applications or 60 days. Stage 1: **checked in the app** (offline). Stage 2: **enforced on the server** |
| 4 | Unlock | **license keys signed by the owner** (Ed25519; private key only in the owner's Keychain); given privately to friends and early adopters |

## Architecture
```
App (public client) ── install id + license key + user's Anthropic key ──▶ Brain API (Cloudflare Worker, private repo)
                                                                          ├─ prompts + logic (score, kit, prep, review, insight, inbox, facts)
                                                                          ├─ allowance meter (D1: install → applications, first seen)
                                                                          ├─ license check (owner's public key)
                                                                          └─ employer index (/index, from the central scout)
```
- **Code:** private `GarryOne/jobadabra-ops` → `brain-api/` (Worker) deployed as `brain` on the owner's Cloudflare.
- **The app** sends inputs and gets results; no prompt text ships in the app after step F.
- **Keys:** the user's Anthropic key goes in the request header, is used for that call, and is dropped. Never logged.

## Allowance and licenses
- **Meter:** applications that reach *Applied* (the app reports each once) and days since the install's first call.
  Free while `applications < 30` **or** `days < 60`. After that, calls that start new work (score, kit, fill, prep)
  answer `402` with the reason. Tracking, reading and export never go through the meter.
- **License key:** `JP1.<base64 payload>.<signature>`; payload `{name, kind: founder|friend|pass, until?}`. The app
  and the API check the signature with the embedded public key: offline in the app, authoritative on the server.
- **Minting (owner only):** `tools/license.py mint --name "Ana" --kind friend [--until 2027-01-01]`, run on the
  owner's Mac; the private key comes from the Keychain (`jobadabra.license.signing_key`). A revoke list lives in D1.
- **In the app:** Settings → License: "12 of 30 free applications · 41 days left", a field to paste a key, and a
  friendly screen when the allowance ends (never mid-application; data and tracking keep working).

## Data ownership
- Notion stays the source of truth for the user's data. The server keeps **only**: install id, counters, first-seen
  date, license id, revocations, the employer index. No CVs, profiles, answers, job texts or keys.

## Risks
- **Trust:** keys through our server. Mitigation: never stored, open client code shows exactly what is sent, a
  privacy page, and Phase 2 included AI removes the need to send a key at all.
- **Availability:** the app needs the API for AI work. Mitigation: Cloudflare Workers, status in Settings, clear errors.
- **Forks:** keep the old public prompts (frozen); acceptable.
