## The change loop
1. `tools/worktree.sh <topic>` (kept after landing; `prune` removes ones on main 7 days; never another session's).
2. Say the tier and the test method (AGENTS.md): Tier 0 touched tests; Tier 1 + one `npm run shot`; Tier 2 (money, store writes, apply flow, installer, engine, migrations) the fast loop, CI runs e2e.
3. Tests first for new behaviour and any bug the owner saw (watch it fail); a behaviour change updates its e2e step in the same commit.
4. Land: `tools/ship.sh --background --body=<file>` (also the private repos). The owner merges every PR by hand; never merge it yourself. Wait for `^ship: (DONE|FAILED|REVIEW|MERGED|CLOSED|RED|GREEN|READY|CONFLICT|COMMENT|GITAR STALE)` with `tools/ship-wait.sh <log>` in the background, again after each event (a Monitor ends after 30 min); call a PR ready only on `ship: READY #n <sha>` (checks green, Gitar Approved, no unanswered comment); a red PR is fixed at once (hook `tools/pr-red-check.sh`; blocked: `tools/pr-red-ack.sh <n> "<why>"`). Commit subject ≤ 72 chars, imperative; 2+ commits → `--title="<what it does for the user>"`. **PR descriptions** are read in 2–5 s. Body (`tools/pr-body-template.md`, check `tools/pr-body.sh origin/main --body=<file>`): verdict line, **Why:**, **Unblocks:**, impact table, 2–4 bullets, Before/After (images when a screen changed, or "No screenshots: <why>"). Never a CI e2e by hand except one fixed Linux suite on your PR ([docs/rules/change-loop.md](docs/rules/change-loop.md)).
5. After landing, only what applies: Decision Log row for an owner decision that changes what agents may do; Bug Tracker row for a UI bug the Finder missed; Intelligence page when a user-visible AI step changes; the to-do list after a finished task.
6. Big changes: spec with `## Progress`, safety net first, ONE full run at landing, 1–3 commits. A multi-PR plan names every PR up front (n/N, a few words each); each PR is titled `[xx] n/N <what>` and carries the template's "Plan progress" block (done / this PR / left), checked by `tools/pr-body-check.py` (owner, 28 Oct 2026).

## Tests in CI (summary)
CI runs the python, worker and desktop suites; one required check, "All checks passed" (`tools/pr-verdict.py`). PRs run unit + integration, plus the e2e steps a PR adds or changes on Linux (`pr-e2e-steps.yml`); journeys run after each merge on main, in the night burn-in and the beta; a PR also runs every harness test file when it changes what one reaches (`harness.yml`); a PR's own jobs run under 10 min (`CI-budget: <why>` to exceed). Push hooks run fast pure checks (`SHIP_PR=1`); the full gate is `PUSH_FULL=1`. Detail and guards: [change-loop.md](docs/rules/change-loop.md).
